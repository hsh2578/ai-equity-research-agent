# 위닝펀드 Word 리포트 생성 스킬 (`/wf-report`)

## v5.5 신설 도구 연결 (2026-09)

`/wf-report` 는 `/research` 와 데이터 수집·analysis.json 을 공용하므로 아래가 그대로 적용된다.

### 정독 의무를 실행 가능하게 (가장 큰 변화)

이 스킬은 "산업 3+ / 기업 3+ 애널리스트 리포트 정독"을 의무로 규정하면서 정작
수집기가 없었다. 그래서 종목마다 `_cw_fetch_reports.py`, `_cw_dl.py`,
`_oci_hist_analyst.py` 같은 일회용 스크립트를 새로 짜고 있었다.

```bash
python scripts/fetch_broker_reports.py {종목명} --category 기업 --months 6
python scripts/fetch_broker_reports.py {종목명} --category 산업 --keyword {업종} --months 6
```

-> `data/{종목}/reports_text/{idx}.txt` (전문) + `_broker_reports.json` (목차).
**한경은 IP rate limit 을 건다. `--workers 2 --delay 0.6` 초과 금지.**

### 작성 전 필수 3종

```bash
python scripts/build_snapshot.py {종목명}    # 수치 source of truth. 미수집 항목은 주장 금지
python scripts/evidence_scan.py {종목명}     # 실측 증거 + 반증 (원문 인용 + file:line)
python scripts/decision_log.py context {종목명}   # 같은 종목 과거 콜과 실제 alpha
```

**인용 박스는 `_evidence_scan.json` 의 quote 를 복사한다.** 원문 100% 복사 + 위치가
붙어 있으므로 가짜 인용이 구조적으로 불가능하다 (이 스킬의 "원문 grep 매칭 후 100% 복사"
규칙을 자동화한 것).

### 밸류에이션 전제 검증 (OCI홀딩스 실측 사고)

**밸류에이션의 핵심 전제 수치는 반드시 1차 출처에서 grep 으로 확인한다.**

실측: OCI홀딩스 리포트가 "폴리실리콘 3.5 -> 7만톤 증설(2029년 완료)"을 전제로
목표주가를 산출했는데, DART 공시 3건 전부에 `7만톤` 이 **0건**이었다.
실제 공시는 **5만 6,600톤**이고 그마저 "증설 여부를 결정할 예정" 단계였다.
전제를 정정하면 목표가가 285,000 -> 236,000원(-17.2%)으로 내려간다.

작성 시 규칙: 목표가 산식에 들어가는 캐파·판가·가동률·완공시점은
`grep "{수치}" data/{종목}/_dart_FULL_*.txt` 로 존재를 확인한 뒤 쓴다. 0건이면 쓰지 않는다.

### bear-researcher 서브에이전트

핵심 포지션은 `report-critic` 전에 `bear-researcher` 를 백그라운드 호출한다.
반증 + 실격 조건 5가지 점검 결과를 리스크 섹션과 밸류에이션 감도에 반영한다.

**와이지엔터 실측이 이 규칙의 가치를 보여준다.** PER 밴드는 통계 기준을 통과했지만

| 연도 | 연말 종가 | 지배주주 EPS | PER | 이익 상태 |
|---|---|---|---|---|
| 2022 | 43,850원 | 2,503원 | **17.5배** | 정상 |
| 2023 | 50,900원 | 3,282원 | **15.5배** | 정상 |
| 2024 | 45,800원 | 991원 | **46.2배** | 적자 |
| 2025 | 69,400원 | 1,974원 | 35.2배 | 회복 초기 |

**2024년 종가 45,800원은 현재가와 거의 같은데 배수는 46.2배다. 차이를 만든 것은 분모다.**
그리고 이익이 정상이던 2022~2023년 배수 15.5~17.5배가 Target PER 의 유일한 실측 근거가 된다.
"5년 평균 대비 저평가" 라고 썼으면 이 통찰이 통째로 사라졌다.

### 영업이익이 두 개인 회사가 있다 -- 반드시 분리 표기한다

와이지엔터 2025년 연결:

```
매출총이익 1,866.0억 - 판관비 1,344.5억 = K-IFRS 영업이익      521.5억  (OPM 9.6%)
                        + 기타영업수익 약 192억 = 발표기준 영업이익  713.4억  (OPM 13.1%)
```

**EV/영업이익이 15.8배와 11.6배로 갈린다.** 어느 쪽도 틀리지 않았고 한국채택국제회계기준에서
기타영업수익 포함 여부는 회사 선택이다. **조용히 한쪽으로 통일하지 말고 두 기준을 병기한다**
(v5.0 "발표기준 vs K-IFRS OP 분리 표기 의무", `verify_numbers.py` B15 가 강제).

### 컨센서스 EPS 가 두 개면 비지배지분을 의심한다

와이지엔터 2026E 주당순이익: Wisereport **3,108원** vs FnGuide **2,624원** (차이 15.6%).
전자는 **연결 순이익**, 후자는 **지배주주 순이익** 기준이다.
2025년 순이익 537.5억 중 **168.5억(31.3%)이 비지배 몫**이었다(2024년 7.5%).

**주주가 받는 것은 지배주주 기준이다.** 연결 기준으로 PER 을 계산하면 15.4배지만
지배주주 기준으로는 22.4배다. 밸류에이션은 후자를 쓴다.

### 정상화 이익에서 지분법손익을 빼먹지 않는다

에프에스티 실측: 관계기업 지분 손익이 2023 -47.6억 / 2024 -76.6억 / **2025 -145.4억** 으로
4개 기간 연속 마이너스이고 확대 중이다. 2025년 순손실 -143.3억의 대부분이 여기서 나왔는데
**영업이익만 보고 정상화 EPS 를 876원으로 계산했다가 552원으로 정정**했다(-37%).

목표주가 25,500 -> 21,000원, 투자의견 HOLD -> SELL 로 바뀌었다.
**영업이익 -> 세전이익 사이에 무엇이 끼어 있는지 매번 확인한다.**

### 급락/급등 직후 종가를 유일한 앵커로 쓰지 않는다

- 한국콜마(과거): 하루 +10.91% **스파이크 고점**을 앵커로 HOLD -> 6거래일 만에 전액 되돌림
- LULU(이번): 하루 **-17.4% 급락 직후** 종가가 20일 평균 대비 -15.4%
- 와이지엔터(이번): 20일 평균 대비 **+8.2%** 인 반등 구간

### bear-researcher 결과는 반드시 1차 출처로 재검증한다

3종목 전부에서 **투자의견을 바꾸는 반증**이 나왔고, 동시에 **에이전트 자신의 오류도 섞여 있었다.**

| 종목 | 반증 결과 | 검증 |
|---|---|---|
| 에프에스티 | 지분법손실 누락 / 장비부문 -17.9% 역성장 / "자사주 소각 없음" 사실오류 / "전액 차입" 사실오류 | 4/4 원문 확인 -> HOLD **-> SELL** |
| LULU | IEEPA 판결이 이미 종료 / Q1 comp 를 -4% 로 오기(실제 +1%) / 자사주 $695.1M 미열람 / 리스부채 미반영 / BPS 시점 혼합 / 매장 수 오기 | 6/6 원문 확인 -> HOLD **-> SELL** |
| 한국콜마(과거) | "FCF 0회" 가 부정확 (실제 `잉여현금` 20회) | 부분 오류 |

**인용에 `file:line` 이 붙어 있으므로 중대 결함은 반드시 `sed -n '{line}p' {file}` 로 직접 본다.**
에이전트가 강세 방향으로 정직하게 자진 보고한 것(에프에스티 오로스테크놀로지 미실현 평가익
+509억, LULU 순현금 $1,389.7M)도 함께 반영한다 -- 반증만 골라 쓰면 그것도 편향이다.

### 셀사이드 컨센서스의 낙관 편향은 실측으로 인용할 수 있다

와이지엔터 Wisereport 2026-05-18: **19개사 매수 19 / 중립 0 / 매도 0**, 평균 목표가 78,789원.

그 컨센은 이미 5월에 두 번 하향된 뒤였다.

**컨센서스를 인용할 때는 `as_of` 를 함께 쓰고, 경과 기간이 1개월을 넘으면 현재 컨센으로
취급하지 않는다** (v5.4 규칙 16). 재수집이 실패하면 실패했다고 쓴다.

### 도구 자체의 조용한 결함 -- 이번에 고친 것들

`/wf-report` 도 같은 도구를 쓰므로 아래는 전부 이 스킬에 영향을 준다.

| 도구 | 결함 | 영향 |
|---|---|---|
| `build_snapshot.py` | KR 손익을 1e8 로 한 번 더 나눔 | **모든 KR 스냅샷의 매출/영업이익/순이익이 0** (풍산 5조 -> "0") |

새 도구를 스킬에 연결했으면 **실제 종목으로 한 번은 끝까지 돌려봐야 한다.**

## 파이프라인

### PHASE A0 -- 애널리스트 리포트 정독 (의무, 작성 전)

리포트의 서사·수치·논거는 **최신 증권사 리포트를 직접 정독해 "참고"**한다(전재 금지, 재구성).
기존 analysis.json 을 7일 이내 재사용하는 경우는 생략 가능하나, 신규/재작성은 의무.

1. **수집 대상 (최소)**:
   - **산업 리포트 3개 이상** -- 해당 종목 섹터의 **심층 산업분석**, 가급적 **40페이지+**, **최근 3개월 이내**. 그래프·도표·시각자료까지 분석.
   - **기업 리포트 3개 이상** -- 본 종목 개별 커버리지(목표주가·밸류 방법·세그먼트 추정 등). 목표주가 스펙트럼과 **밸류 방법**을 확보한다 -- 스펙트럼은 시나리오(Bear/Base/Bull) 현실성 *점검*용이고, Base는 레버 3으로 **자체 산출**한다(브로커 목표가 복붙 ❌, 컨센은 stale 주의·레버 4).
2. **탐색**: `WebSearch` 로 "{섹터} 산업 리포트 2026 in-depth/산업분석", "{종목} 증권사 목표주가" 등. 한경컨센서스·증권사 PDF(hanaw 등)·alphasquare·iprovest 처럼 **직접 다운로드 가능한 PDF URL** 우선.
3. **다운로드·정독**: `data/{종목}/reports/` 에 PDF 저장(`curl -sL -A "Mozilla/5.0" {url} -o ...`).
   - 텍스트: `fitz`(PyMuPDF) 로 페이지 추출 → `_extract_*.txt` 저장 후 Read 로 정독.
   - **차트/그래프 시각 분석(의무)**: 핵심 페이지를 `fitz` 로 PNG 렌더(`page.get_pixmap(matrix=fitz.Matrix(2,2)).save(...)`) 후 Read 로 **수치까지 파악**(가격·점유율·밸류·SOTP 차트). poppler/pdftoppm 미설치 환경에선 **fitz→PNG 가 표준**(Read 의 네이티브 PDF 렌더는 PATH 제약으로 막힐 수 있음).
4. **반영 (내용 성격으로 유동 배치, 전재 금지·재구성)**: 정독한 리포트(산업·기업)와 `WebSearch` 결과는 모두 **소스**다. **리포트 종류로 섹션을 고정하지 말 것** -- 내용의 *성격*으로 배치한다. 산업 리포트라도 그 회사 관련 부분은 기업분석/투자포인트에, 기업 리포트라도 산업 동향 부분은 산업분석에, WebSearch(정책·선거·관세·근황 등)는 성격에 맞는 섹션에 유동적으로 넣는다. 어느 섹션도 문장을 그대로 옮기지 말고 **논거·데이터의 *원리*를 이해해 우리 서술로** 재구성한다.
   - 대략의 경향(고정 아님, 네가 분석해 판단): 밸류체인·수급·규제·수요 동력 → 산업분석 / 사업구조·세그먼트·약점→해소(레버 1) → 기업분석 / 밸류 방법(레버 3) → 밸류에이션 / 촉매 → 투자포인트·촉매 / 변동·리스크 → 리스크.
   - 리포트 차트의 데이터는 **추출해 자체 도표로 재생성**(스크린샷 대신 wf_charts 도표). 모든 수치에 **출처·발표시점** 명시.
5. **심층 재독(요약만 읽지 말 것)**: 첫 정독에서 총평/요약만 보고 넘어가면 핵심 논거의 *근거*를 놓친다. 사용자가 특정 리포트를 지목하면 본문까지 심층 재독한다 -- 기업 리포트는 **SOTP·밸류 산식·세그먼트 추정**을, 산업 리포트는 **핵심 주장의 정량 근거**(예: "규제완화 불가 5대 근거", FEOC로 미국 모듈 40% 도태)를 본문에서 추출해 반영. (OCI 세션 실증: 하나 49p의 "중국 규제완화 불가" 논거를 1차에 누락 → 본문 재독으로 5대 근거 확보.)
6. **데이터 시점 = 발간 시점이 아니라 "현재 시점"**: 산업 수치·정책·선거·관세 등은 참고 리포트 발간일이 아니라 **작성 당일 기준으로 `WebSearch` 재확인** 후 본문/caveat 갱신(예: "Section 232 폴리 6월 말 발표 임박, 제안 $10/kg + 40,000톤 쿼터"). 30일+ 경과치는 "현재 변동 가능" 부기.
7. **DART 전자공시 사업보고서 정독 (1차 출처, 의무 -- 「I. 회사의 개요」+「II. 사업의 내용」 전수, 소제목만 보지 말 것)**: 회사가 직접 쓴 1차 사실이라 기업분석·산업분석·리스크의 **최우선 근거**(애널리스트 리포트보다 우선).
   - **⚠️ 함정 -- 요약 추출은 truncate + 회사 개요 누락**: `get_all_reports()` 가 만드는 `data_dart_reports.json` 은 섹션을 잘라 저장하고(사업의_내용 15,000자 cap 등), '사업의 내용' 키워드부터 추출해 **「I. 회사의 개요」(회사의 연혁·자본금 변동사항·주식의 총수·정관)를 통째로 놓친다**. 요약본만 보면 전수 정독이 아니다.
   - **전문 받기 (의무)**: `download_report_document(rcept_no)` + `html_to_text` 로 **cap 없는 전체 문서**(수십만 자)를 `_dart_FULL.txt` 로 저장한 뒤, grep 으로 소제목 위치를 잡고 해당 구간을 Read 로 정독한다. **「I. 회사의 개요」**(회사의 연혁·자본금 변동·주식의 총수·정관·자사주 소각/배당)와 **「II. 사업의 내용」**(사업개요·보고부문별 손익/자산·지역별 매출·주요제품·가격변동·생산능력/실적/가동률·매출/판매경로·위험관리·주요계약·연구개발·시장여건)의 **모든 소제목을 다 읽는다**.
   - **1차 데이터 체크리스트**(읽으며 뽑을 것): 지역별 매출(수출 구조)·사업부문별 매출/영업손익/자산·부채·생산능력(CAPA)/가동률·제품 가격추이·시장점유율·자사주 소각/배당(주주환원)·주요계약·증설 결의·위험요인. 분기보고서로 분기 실적·증설 시점 대조.
   - **인용 박스(`>`)**: 원문 grep 매칭 후 **원문 100% 복사**(의역·어미 추가 금지). 출처 `> 사업보고서 II. 사업의 내용 (YYYY/MM 공시): "..."`. 섹션당 ≤2건, 나머지는 풀어써 우리 서술로. `report_extractor.py` 는 보조.
   - (OCI 세션 실증: 요약본만 보면 'DCRE 영업이익 +881억·미국향 매출 +54%·자사주 5차례 소각·도시개발 부채 1.17조' 같은 결정적 1차 데이터를 놓친다 → 전문 정독으로 확보·정정.)

## 위닝펀드 7섹션 구조 (필수)

산출 리포트는 위닝펀드 덱 포맷의 **7섹션 흐름**을 따른다(top-down: 산업 → 기업, 리스크가 밸류 앞):

> **1. 요약 → 2. 산업 분석 → 3. 기업 분석 → 4. 투자 포인트 → 5. 재무 분석 → 6. 리스크 → 7. 밸류에이션**

- 내부적으로는 **v5.0 12섹션 키를 그대로 작성**(verify_style/facts/numbers 호환)하되, 빌더에서 보조 섹션을 호스트에 **병합**하고 `meta.section_order` 로 렌더 순서를 지정한다.
- **병합 맵** (빌더 하단에서 `_demote()` 로 맨 위 `##` 만 `###` 강등 후 append -- 내부 `###` 는 유지해 차트 매칭 보존):
  ```python
  def _demote(md):  # 맨 위 ## 만 ### 로 (내부 ### 소제목은 유지)
      return re.sub(r'^##\s', '### ', md.strip(), count=1)
  s['s03_company_overview'] += "\n\n" + _demote(s['s05_management_fieldcheck'])                       # 경영전략 → 기업분석
  s['s06_financial'] += "\n\n" + _demote(s['s10_earnings_consensus']) + "\n\n" + _demote(s['s11_supply_shareholder'])  # 실적·컨센+수급 → 재무분석
  s['s07_valuation'] += "\n\n" + _demote(s['s12_action_plan'])                                         # 액션플랜 → 밸류에이션
  # ESG(s08) 는 본 포맷 제외(키는 유지하되 section_order 에서 빼 미렌더)
  ```
  **병합은 alias 재생성 전에 수행**(alias 가 병합된 본문을 복사하도록). 원본 키(s05/s10/s11/s12)는 verify 호환 위해 그대로 둔다.
- **`meta.section_order`** (generate_word_wf.py 가 읽음; **미지정 시 기존 12섹션 CANON** -- 다른 리포트 무영향):
  ```python
  meta['section_order'] = ['s01_opinion_thesis','s04_industry_competition','s03_company_overview',
      's02_thesis_catalysts','s06_financial','s09_scenarios_risks','s07_valuation']
  ```

**분석의 실질(비교·산정·점검)은 깊게 유지하되, 서술은 PHASE A0 에서 정독한 증권사 리포트(교보·삼성) 톤을 따른다 -- 깔끔한 평서 산문 + 데이터 표.** 위닝펀드 특유의 장식(★채점표·`### 한 줄 평가:`·`시사점:` 라벨·`> 위트 인용`)은 **절제·제거**한다. (이전 버전은 이 장식들을 verify_style 점수로 보상해 강요했으나, 실제 일류 애널리스트 리포트는 장식 없이 산문+표로 푼다. OCI 작업에서 사용자 지정으로 톤 전환.)

핵심 섹션에 아래 분석 틀을 **표 형태**로 내장한다(틀은 유지, 장식만 제거):

- **★ 강도 표기 금지**: 비교 표의 평가 열은 ★ 대신 텍스트(매우 강함/강함/보통/약함, 우위/열위)로.
- **top-down 빌드업**: 매크로 → 밸류체인/구조 → 종목으로 쌓아 올린다(교보식). 단락 안 번호 논거(1)2)3))도 참고 리포트 방식.
- **유지하는 분석 실질**(참고 리포트도 하는 것): 벤치마크 비교, 수치+델타("+25% YoY", "$25.3 → $12.7/kg"), 약어 1회 풀이("영업이익률(OPM)"). `→` 는 보존되니 델타에 사용.

## 서술 접근성 -- 가르치듯, 단 '메타 라벨' 없이

산업을 처음 보는 독자도 따라올 수 있게 **개념을 처음부터 자연스럽게 풀어 설명**한다(PHASE A0 에서 정독한 산업 리포트의 강점 차용 -- 교보 신재생처럼 매크로 → 밸류체인 → 투자로 쌓아 올린다).

- **메타 라벨 금지(중요)**: "처음 보는 분을 위한", "한 문장 요약:", "쉽게 말하면", "일반 독자를 위한", "어렵게 들리지만" 등 **설명한다는 사실 자체를 알리는 문구는 쓰지 않는다**. 참고한 증권사 리포트는 그런 라벨 없이 그냥 자연스러운 본문으로 푼다. 같은 내용을 라벨 없이 서술로 녹인다.
  - X: "**처음 보는 분을 위해 한 문단으로.** OCI는 폴리실리콘을..." / "**한 문장 요약:** ..." / "핵심을 쉽게 말하면..."
  - O: "OCI홀딩스는 태양광 패널의 핵심 재료인 폴리실리콘을 말레이시아에서 만드는 회사다. 이 재료는 중국이 세계의 92%를 만든다. 그런데..."
- **개념 풀이는 단계로 담백하게**: 밸류체인 4단계(폴리실리콘 → 웨이퍼 → 셀 → 모듈), 규제는 '이름(한 줄 기능)' 형식(예: UFLPA = 강제노동 제품 수입금지)으로 푼다. **과한 비유(밀가루·도장 등)·구어체("쉽게 말해")는 절제**하고 참고 리포트처럼 담백한 산문으로.
- **첫 등장 약어는 괄호 한 번**(C2): IRA(인플레이션감축법)·ASP(평균판매단가) 등. 약어 풀이도 문장 안에서 자연스럽게.

## 리포트 품질 레버 (범용 -- 예시는 OCI·YG, 기법은 종목 불문)

YG 18-1기(엔터/IP)와 OCI(지주/소재) 두 리포트에서 검증된 품질 레버. **기법(형태)은 섹터·종목 유형 불문 적용하되, 내용은 대상 종목의 고유 약점·촉매·밸류 방식으로 채운다.**
> **경고: 아래 OCI/YG 예시를 복붙하지 말 것.** 예시는 기법의 '형태'만 보여준다 -- "같은 형식, 다른 내용". 종목 유형 분기는 `CLAUDE.md` 절대규칙 18(지주/적자/순현금/저베타/사이클/Hybrid/단일)과 연동해 적용한다.

### 1. 기업분석 = "오래된 한계 → 지금 해소 → 재분류" 논증 아크
서술형("회사가 뭘 하나")이 아니라 **논증형**으로: (a) 오래된 구조적 약점 → (b) 그 약점이 지금 왜·어떻게 풀리나(**정량 증명**) → (c) 그래서 시장의 *분류*가 바뀐다. 소제목은 라벨이 아니라 **주장**으로.
- YG(엔터): 소수 IP·긴 공백(한계) → 시스템 개편·컴백 5배 단축·베몬 정량 증명(해소) → "라인업 두께가 변한 회사" 재분류.
- OCI(지주/소재): 폴리=중국 92% 범용재(한계) → 비중국 규제·우주 수요·수직계열화(해소) → "범용 소재 → 안보 자산" 재분류.
- (다른 유형 예: 적자 턴어라운드주 = 적자 원인 일회성 입증 / 저PBR 자산주 = 숨은 자산 부각 등 -- 같은 아크, 다른 약점.)

### 2. 주가가 크게 움직인 종목 = "변동 진단" 프레임
급등/급락 종목은 요약/리스크에 (a) 변동 요인 N개 분해 → (b) 각각 *일시적/지속적* 판정 → (c) 회복(또는 추가하락) 경로. (YG "멀티플 깎인 3가지 → 회복 트리거 4가지" / OCI "급락 3요인 → 일시적 → 2Q 회복".) **안 움직인 종목엔 생략** -- 모든 종목에 강제하지 말 것.

### 3. 밸류에이션 = 그 회사 애널리스트가 쓰는 방법을 '원리로' 이해해 자체 산출
밸류 방법을 종목 유형에서 *추측*하지 말고, **PHASE A0 에서 정독한 기업 리포트 3건+에서 각 증권사가 실제로 쓰는 밸류 방법과 그 이유를 먼저 분석**한다. 3단계로:
1. **무슨 방법을 쓰나** -- 커버 애널리스트들이 주로 쓰는 산식을 추출(목표가 산출 근거). 예(OCI): 삼성=SOTP / 교보=Target PER / 유진=BPS×PBR / 하나=EV/EBITDA → **지주라 SOTP가 지배적**.
2. **왜 그 방법인가** -- 그 회사의 손익 구조·자산 구성에 맞는 *이유*를 이해한다(지주는 사업부가 다른 멀티플이라 SOTP, 사이클·소재는 당기 EPS가 왜곡돼 정상화 EPS·EV/EBITDA, 성장주는 미래이익이라 Forward PER·DCF, 자산주는 보유자산이 핵심이라 NAV). **아래 표는 "왜"의 참고용**이지 추측의 출발점이 아니다.
3. **원리를 우리 산출로 옮긴다** -- 브로커 산출값을 베끼지 말고, **입력값만 넣으면 재현되는 단계 계산**으로 직접 도출(예: SOTP라면 사업부별 EBITDA×배수 → 합산 − 순차입 ÷ 주식수).

| 종목 유형 | 애널리스트가 주로 쓰는 방법 | 그 이유(원리) |
|---|---|---|
| 지주·복합 | SOTP | 사업부마다 적정 멀티플이 달라 단일 PER 왜곡 |
| 단일사업·성장 | 정상화 EPS 분해 × Target PER | 이익 가시성↑, 미래 EPS가 핵심 |
| 사이클·소재 | mid-cycle 정상화 EPS, EV/EBITDA | 당기 EPS가 사이클로 왜곡 |
| 자산주·리츠 | NAV | 손익보다 보유자산 시장가가 본질 |
| 고성장·적자 | DCF, Forward 멀티플 | 당기 적자라 PER 무의미 |

어느 방법이든 **(입력 → 단계 계산 → 출력 + 감도 분석)** + **Python 산술 검증** + verify B12. 방법이 갈리면 **교차검증 표**(방법별 산출가 스펙트럼)로 보이고 1순위를 명시. **near-term Forward PER이 비싸면 솔직히 인정**하고 가치 근거를 정상화·자산·옵션으로 분리한다(OCI critic 교훈: **EPS를 부풀려 "저평가"를 만들지 말 것** -- 순이익이 이자보상배율 등 자기 서술과 산술적으로 모순되면 안 됨).

### 4. broker명은 본문에서 제거, 컨센서스는 집계로
"X증권에 따르면/(삼성)/(교보)" 등 특정 broker 인용 제거, 우리 자체 서술(일반 "증권사"는 허용). per-broker 표 대신 **범위/티어 집계**(목표가 범위·평균 + 본 리포트 위치). **컨센은 stale 주의 -- `financial_summary.json` 의 현행 목표가/EPS로 갱신**(OCI critic 교훈: 3개월 전 목표가·단일 브로커 EPS를 현재 컨센으로 쓰지 말 것). 실측: 렌더 섹션 broker명 0회 grep 체크.

### 5. report-critic 가혹 비평 (핵심 포지션 권장)
verify 3종 통과 후 `report-critic` 호출. 프롬프트는 **파일 경로 + "최고의 애널리스트 관점에서 냉정하고 객관적으로 평가해줘. 더 수정할 내용 없어?"** 한 문장만(가이드 금지 -- CLAUDE.md STEP 6 철학). critic 지적은 빌더 Edit 후 재빌드로 자동 정정. critic는 특히 **숫자 내부모순(이자보상배율 vs 순이익)·컨센 정합·민감도 미공개**를 잡는다.

## 검증 사전 정렬 (verify FAIL 차단 -- 실측 함정)

빌더에서 미리 맞춰두면 재작업이 없다:
- **B2 현재가**: `price.current` = 수집 직후 KIS 현재가. 수집~검증 사이 시세가 움직이면 FAIL → 빌드 직전 `get_current_price` 로 갱신.
- **B6 순현금/순차입**: verify 가 `financial_summary.json` **최신 기간**의 `net_debt` 를 읽어 s06(=s08_financial)에서 **"순현금"/"순차입" 단어 + 조 단위 숫자(±10%)** 를 찾는다. 반드시 s06 에 `순차입 약 0.25조` / `순현금 약 0.32조` 처럼 **최신 분기값을 "조"로** 명시(억으로만 쓰면 FAIL).
- **B10 R/R 일관성**: `opinion.risk_reward` 의 % 와 비율이 **현재가 기준 실제 계산**과 일치해야 함. 현재가 바뀌면 Base/Bear % 재계산. Executive Summary 표의 동일 수치도 함께 갱신(s01 표는 opinion 과 별개로 하드코딩되니 누락 주의).

## 주의

- **`→`(화살표)·`★☆`(별점)은 보존된다 -- 적극 사용**: 이 세션(2026-06)에 `generate_word_wf._EMOJI` 와
  `verify_docx._EMOJI` 를 패치해 화살표(U+2190~21FF)와 별점(★U+2605·☆U+2606)을 strip 대상에서 제외했다.
  - **`→` 는 verify_style C15(메커니즘)·C19(좋은 패턴)가 세는 글자**이므로 델타/전환 표기에 적극 쓴다.
    띄어쓰기로 감싸 가독성 확보(`매출 502 → 503억`, `수출 38.9% → 56.9%`). C19 크레딧은 "맨숫자 → 맨숫자+단위" 형태가 확실.
  - **`★☆` 별점은 Word 에 정상 렌더**되나(EMOJI strip carve-out), **참고-리포트 톤에선 비교 표 평가 열에 ★ 대신 텍스트(매우 강함/강함/보통/약함)** 를 쓴다(`## 분석 깊이 + 참고-리포트 톤`).
  - (역사 메모) 과거엔 둘 다 strip 돼 `500→750`→`500750` 병합 + 해자표 ★ 강도 열 **공백** 사고가 있었다. `->`(ASCII)는 C15/C19 가 못 세니 쓰지 말 것.
- **순현금 착시 (결제 자회사 연결 / 지주)**: 연결 순현금에 결제 자회사(예: 헥토파이낸셜) **정산 예수금**과
  **소수주주 귀속분**이 섞일 수 있다. 액면 "순현금 > 시총"으로 단정 말고 **SOTP + 예수금 caveat**(s06/s07/s09)로 보수 처리.
  자회사가 별도 상장이면 **SOTP(지분 시장가 + 본업 + 별도순현금)** 가 단일 PER보다 정확하다.
- **폴더명 == `meta.stock_name`**: planner/word-gen 모두 `data/{stock_name}/`, `output/{stock_name}/` 를 쓴다.
  CLI 인자 `{종목}` 은 `scripts/analysis_{종목}.json` 위치를 찾는 용도이므로 둘이 달라도 되지만 경로 일관성에 주의.
