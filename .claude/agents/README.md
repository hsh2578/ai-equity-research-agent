## v3 → v4 전환 이유

### "서브에이전트로는 해결되지 않는 문제"

v3로 기아 리포트를 작성한 후 사용자는 지적했다:
> "회사개요랑 산업분석 투자포인트 질이 안 좋아서 에이전트를 고민한건데 내용은 좋기는 한데 엄청난 개선이 일어난거 아닌거 같은데 어떻게 생각해?"

냉정한 진단:
- **s03 약점의 진짜 원인**: 사업보고서 [0] `주요_계약` 섹션에 지역별 매출/M/S/판매대수 테이블이 통째로 들어있었는데, 에이전트 구조와 무관하게 **Grep을 안 한 것**
- **s04 약점의 진짜 원인**: 산업 일반론만 쓰고 "본 종목의 글로벌 포지셔닝"을 결합하지 않은 것
- **s02 약점의 진짜 원인**: 4줄 구조(주장/근거/왜주가/시장간과)를 엄격히 적용하지 않은 것

**셋 다 에이전트를 6개로 나눠도 안 풀리는 문제였다.** 프롬프트 품질과 데이터 채굴 지시의 문제였다.

### 검증: 기아 s02/s03/s04 수술

v3 에이전트 구조를 그대로 두고, **메인 에이전트가 직접 사업보고서 [0] 주요_계약을 Grep → s02/s03/s04만 재작성** 실험:

| 섹션 | v3 에이전트 출력 | 수술 후 | 증가 |
|---|---|---|---|
| s02 투자포인트 | 2,083자 | 3,628자 | +74% |
| s03 회사개요 | 1,415자 | 3,100자 | +119% |
| s04 산업분석 | 2,428자 | 3,819자 | +57% |

추가된 내용:
- 지역별 매출 테이블 (국내 28.82조, 북미 KUS 39.41조, 유럽 23.28조 등)
- 5개 지역 M/S (국내 34.2%, 미국 5.1%, 유럽 4.0%, 인도 6.4%, 중국 0.3%)
- ASP 3년 추이 (32.2 → 33.6 → 34.9백만원)
- 신용등급 상향 궤적 (Moody's Baa1→A3, S&P BBB+→A-)
- 지적재산권 25,231건
- 부동산 개발업 신규 목적사업

**이 모든 데이터는 에이전트가 있든 없든 사업보고서에 이미 있었다.** Grep 지시만 있으면 단일 에이전트로도 동일 품질 도달 가능 확인.

→ v4로 복귀 결정, 서브에이전트 6개 파일 삭제.

## 언제 서브에이전트로 돌아갈 것인가

단일 에이전트 v4로도 기아 수준이 안정적으로 재현 안 되는 경우에만 재고한다. 그전까지는 **프롬프트 수술로 해결**이 원칙.

서브에이전트가 정당화되는 경우:
1. 단일 컨텍스트가 실제로 포화 (50K+) — 현재 100~120K 토큰 한계 내에서 문제 없음
2. 진짜로 서로 독립적인 분석 작업이 있음 — 리서치 리포트는 통합 사고가 필요한 영역이라 해당 안 됨
3. 병렬화가 시간상 critical — 개인 리서치 도구이므로 5~10분 단축 무의미
