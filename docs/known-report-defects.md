# 발간 리포트의 알려진 결함

v5.5 에서 죽어 있던 검증(B13 분기 누락)을 복구하자 기존 리포트에서 결함이 드러났다.
여기 기록해 두는 이유는, 고치지 않고 넘어간 것을 나중에 "몰랐다" 고 하지 않기 위해서다.

`python scripts/verify_numbers.py {종목}` 으로 언제든 재확인할 수 있다.

## 상태

| 종목 | 발간일 | 결함 | 상태 |
|---|---|---|---|
| 기아 | 2026-04-10 | 분기 라벨에 연도가 없어(`Q1~Q4`) 표가 자립하지 못함 | **수정 완료** (2026-09-08) |
| 두산 | 2026-04-20 | 확정 분기 3개(2Q25/3Q25/4Q25) -- **1Q25 누락**으로 YoY 비교 불가 | 미해결 |
| 에코프로 | 2026-04-10 | `quarterly` 표 자체가 없음 | 미해결 |
| OCI홀딩스 | 2026-05 | 밸류에이션 전제 "3.5 -> 7만톤 증설(2029)" 이 **DART 공시 3건 어디에도 없음** (실제 공시는 5만 6,600톤 + "증설 여부 결정 예정") | 미해결 |
| 한국콜마 | 2026-08-29 | EPS 교차검증 실패 -- 시세 API 5,299원 vs 재무 API 4,575원 (15.8% 괴리) | 미해결 |

## 기아 -- 수정 내역

`quarterly.headers` 를 `['', 'Q1', 'Q2', 'Q3', 'Q4', '연간']` 에서
`['', '1Q25', '2Q25', '3Q25', '4Q25', '연간']` 로 바꿨다.
데이터는 원래 완전했고 연도가 `quarterly.year` 필드에만 있어 표가 자립하지 못했던 것이다.
수정 후 B1~B18 전체 통과. 원본은 git 이력에 있다 (`git show HEAD~1:scripts/analysis_기아.json`).

## 두산 / 에코프로 -- 왜 안 고쳤나

**없는 데이터를 지어내지 않는다.** 이 프로젝트의 원칙이다.

- 두산 1Q25(2025/03) 는 발간 시점(2026-04)에 이미 존재했으므로 **진짜 수집 누락**이다.
  다만 복구된 FnGuide 는 최근 4분기만 제공한다(실측: 2025/09 ~ 2026/06). 소급 불가.
- 에코프로는 분기표를 처음부터 만들지 않았다.

두 종목 모두 제대로 고치려면 **DART 분기보고서를 다시 수집해 리포트를 재작성**해야 한다.
5개월 지난 리포트를 오늘 데이터로 부분 패치하면 시점이 섞여 더 나쁘다
(확정 실적과 추정치를 같은 표에 섞지 않는다는 규칙에도 어긋난다).

재작성할 때는 `/research 두산` 을 그냥 다시 돌리면 된다.

## OCI홀딩스 -- 가장 심각

`bear-researcher` 가 찾았고 내가 원문으로 독립 검증했다.

- 리포트가 "7만톤" 을 25회, "2029" 를 35회 주장하며 목표주가 산식의 전제로 썼다
- DART 공시 3건(사업보고서/1분기/3분기) 전부에서 `7만톤` **0건**
- 실제 공시는 "3만 5,000톤에서 **5만 6,600톤**까지 확대할 계획이나 ... 증설 계획 실행 시점을 조율할 예정"
- 전제를 정정하면 목표가 285,000 -> 236,000원(-17.2%), 할인율까지 바로잡으면 186,000원

이건 라벨 문제가 아니라 **밸류에이션 결론이 바뀌는 사안**이라 리포트 재작성이 필요하다.

## 재발 방지

- B13(분기 누락)은 v4.20 부터 죽어 있었다. `scripts/quarter_labels.py` 로 복구하고
  `tests/test_quarter_labels.py` 45개로 고정했다.
- 밸류에이션 전제 수치는 `grep "{수치}" data/{종목}/_dart_FULL_*.txt` 로 존재를 확인한 뒤 쓴다.
  0건이면 쓰지 않는다 (`.claude/commands/wf-report.md` v5.5 절 참조).
- `scripts/evidence_scan.py` 가 원문 인용에 `file:line` 을 붙여 가짜 인용을 구조적으로 막는다.
